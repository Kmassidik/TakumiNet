## 1. What I found (evidence)

The UI looks like Packet Tracer because most of it **is** Packet Tracer's art,
loaded at runtime from the mounted vendor tree (`/assets/...`), not drawn by us.

| Surface | Where | Source today |
|---|---|---|
| Logical device icons | `src/workspace/palette.rs::logical_art` (32 kinds, `art/Workspace/Logical/i*@2x.png`), sent to the browser in the workspace JSON | Cisco PNG |
| Logical device icons (own) | `web/art/*.svg`, 31 files, via `logical_icon` | Ours, flat 32px line icons |
| Toolbar | `web/js/toolbars.js`, 27 buttons (`art/Toolbar/iTB*.png`) | Cisco |
| Simulation controls | `web/index.html` (8 `<img src="/assets/art/Simulation/...">`) and `web/js/actions.js` | Cisco |
| Palette tiles | `web/js/palette.js` (`art/ComponentBox/*.png`, driven by `catalog.rs` reading `.ptd` templates) | Cisco |
| Device window apps | `web/js/device_window.js`, 15 icons (`art/Workstation/*.png`) | Cisco |
| Physical (rack) view | `web/js/device_tabs.js` (`art/PhysicalView/Devices/*`) | Cisco |
| Sounds | `web/js/state.js` (`Sounds/*.wav`) | Cisco |
| App logo and title | `web/index.html` line 13: `/assets/art/app.png` and the text "Cisco Packet Tracer" | Cisco |

**Measured in a real browser (Claude in Chrome, 2026-11-03, no vendor tree mounted):**
loading the page and opening one device window makes **99 distinct `/assets/...`
requests and all 99 fail (HTTP 503)**: 1 logo, 6 simulation, 27 toolbar, 18
palette (`ComponentBox`), 31 logical icons, 15 desktop apps, plus the rest. The
toolbar, palette tiles, simulation buttons and desktop-app icons render as
broken images. The canvas, device window, CLI and ping still work. No console errors.

Consequences:
1. Without the mounted tree (as in the Docker run you just did) the toolbar,
   palette, simulation buttons and desktop apps render **broken images**. Only
   the canvas icons work, because those have own-art fallbacks.
2. `README.md` and `web/art/README.md` set the project rule: **own art, rebuilt
   from scratch**. The current UI contradicts it.
3. "Make it 3D" must not mean restyling Cisco's files. A 3D version traced or
   AI-restyled from their PNGs is still derived from them. **Every 3D asset must
   be drawn from our own geometry.** (This is a project-policy point, not legal advice.)

## 2. Goals and non-goals

Goals
- G1. Every visible asset in the shipped UI is original and 3D-styled.
- G2. The app runs fully **without** the vendor asset tree (no `/assets/` references in `web/`).
- G3. Every component in the UI either works, or is visibly marked as not available.
- G4. A repeatable check proves G2 and G3 so they cannot regress.

Non-goals
- Re-creating Cisco's exact look, name or logo.
- Real-time WebGL scenes (see decision D1).
- Changing simulation behavior. The audit may fix defects it finds, each in its own commit.

## 4. Asset spec (what Codex is asked to produce)

Common rules for every sheet:
- **Layout:** 3 columns by 2 rows = 6 icons per sheet, equal cells, 1536x1024 px, so each cell is exactly 512x512. No labels, no borders, no text in the picture.
- **Background:** fully transparent PNG. If the generator cannot do transparency, a flat `#00FF00` background that the slicer keys out.
- **Camera and light:** same for all sheets: three-quarter view from front-left and above, key light top-left, soft contact shadow under each object (inside its cell, not cropped).
- **Style:** soft rounded 3D, matte plastic and brushed metal, slightly toy-like, one shared colour palette (base blue-grey, accent teal, warm LED amber).
- **Centering:** object centered, about 80% of the cell, shadow included.
- **Provenance rule:** prompts must describe the object in words only. **No Cisco or Packet Tracer screenshot, icon or file may be given to the generator as a reference.** Each sheet is recorded in `web/art/3d/MANIFEST.json` with its prompt, tool, date and who generated it.
- **Mascot:** one fluffy creature (design left to the owner), delivered as a 6-pose sheet: idle, wave, thinking, happy, error, sleeping. Its idle pose is the app icon and logo.
- **Heads-up on rights:** images produced purely by a generator may have weaker copyright protection than hand-made art. That is the owner's call; the manifest keeps the evidence of how each was made.

Slicer (`tools/slice_sheets.py`, Python with Pillow, which is already on this machine; it will be added to the Nix dev shell so it is reproducible):
- cuts each sheet into 6 cells, trims transparent padding, writes `web/art/3d/<name>.webp` at 256 px (device icons) or 64 px (UI glyphs);
- fails if a cell is empty, off-centre, opaque corners, or over the size budget;
- budget: 40 KB per device icon, 8 KB per UI glyph.

State without separate files (raster cannot split layers): selected, hover and
powered-off are done in CSS (outline glow, `filter: grayscale(1) brightness(.6)`).

## 8. Risks

| Risk | Mitigation |
|---|---|
| Sheets from the generator drift in style between runs | Same prompt prefix and palette for every sheet; pilot approved first; reuse the pilot sheet as a style reference (our own image, never a Cisco one) |
| Generated cells are cropped, uneven or have halo edges | Slicer rejects them with a clear message; regenerate only that sheet |
| Raster weight grows the page | Per-file budget, WebP, lazy-load palette tiles |
| Pure-AI images carry weaker copyright than hand-made art | Manifest records prompt, tool and date; owner decides whether that is acceptable |
| Icons illegible at canvas size | Test at 32, 48 and 64 px; keep silhouette first, detail second |
| Scope creep into "make it exactly like X" | Section 2 non-goals; D2 decided up front |
| Removing the vendor tree breaks features that read it (`.ptd` catalog, `.pkt` import samples) | Those are data inputs, not art. Keep them optional; only art is removed |
| Audit finds many defects | Triage: fix or hide; each fix has a test; defects do not block art PRs |

## Roadmap to "usable like the real one" (decided 2026-11-03)

**Definition of done:** a student can finish a typical CCNA lab end to end: build the topology, configure it only through the IOS CLI, get correct ping/traceroute/show output, watch packets in Simulation mode, save and reopen the file.

**Measured gaps (from the code, not guesses):**
- `workspace/routing.rs::recompute_routing` runs ONE hop-count search for RIP, OSPF and EIGRP alike. No OSPF cost/areas/DR, no EIGRP metric, no AD/floating routes, BGP and HSRP absent, EtherChannel minimal.
- `show` has ~28 commands, one explicit "not implemented yet" fallback (`cli/show.rs:44`). Ping prints a hardcoded `TTL=128`.
- 6 toolbar buttons empty, Programming and Attributes tabs empty, Dialup app empty.

**Method: lab conformance first.** Write `tests/labs/`: ~10 canonical CCNA labs as integration tests (build topology through the API, run CLI scripts, assert pings and key `show` lines). The pass/fail matrix is the work list, so nothing is built on a guess. Expected outputs come from the protocol specs and from behaviour, never copied vendor text.

**Order (each item: failing lab test, then code, then `cargo test`, commit, push):**
1. Core correctness: TTL from the packet, traceroute, ARP, ICMP unreachable and time-exceeded.
2. IOS CLI fidelity: abbreviations, `?` help, mode prompts, `% Invalid input` caret, `show running-config` ordering, `write memory`/`copy run start`, `show` gaps.
3. L2: VLAN/trunk/router-on-a-stick, STP/RSTP root election (IEEE bridge ID compare), EtherChannel.
4. Routing, replace the shared search with real algorithms, each with property tests:
   - Static/default with administrative distance and floating routes.
   - RIPv2: Bellman-Ford, 15-hop limit.
   - OSPF: LSDB + Dijkstra, cost = 10^8 / bandwidth, single area first, then multi-area.
   - EIGRP: composite metric 256 * (10^7 / min bandwidth + sum delay / 10) (default K values).
   - Property tests: Dijkstra equals brute force on random graphs; converged tables are loop-free; every router's route to a prefix is consistent.
5. Services: verify DHCP/DNS/NAT/ACL with labs (they exist, prove them).
6. Simulation mode parity: PDU list, event filters, per-layer inspection.
7. File interop: open real .pkt, round-trip save (corpus test exists).
8. Remaining UI placeholders and art (art steps 1-4 first, because broken icons hurt now).

**Not now:** BGP, HSRP, IPv6 routing protocols, wireless controller depth: after the CCNA path passes.
